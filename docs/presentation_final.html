ADR Summary · 아키텍처 의사결정
아키텍처 의사결정 기록 (ADR-0001 ~ ADR-0005)
ADR-0001
모바일 · 웹 — Flutter 단일 코드
💡 왜? Android·iOS·Web·Windows를 단일 코드베이스로 지원하고 AMOLED 다크 테마 및 커스텀 차트/해부도 렌더링 일관성 확보
✅ 결과: 모바일 앱과 EC2 정적 웹 데모(SPA)를 동시에 릴리즈, 핫 리로드로 UI 개발 속도 극대화
ADR-0004 (Supersedes 0002)
단일 백엔드 — FastAPI + PostgreSQL
💡 왜? 초기 Java(8080)+Python(8000) 이중 서버의 오버엔지니어링과 DTO 중복 비용을 교수님 피드백 반영해 포트 8000 하나로 통합
✅ 결과: 개발 생산성 3배 향상, AWS 프리티어 EC2(RAM 1GB)에서 OOM 없이 24/7 안정 가동
ADR-0003
AI 엔진 — 5단 멀티 LLM + 스마트 폴백
💡 왜? 외부 LLM 장애·할당량 초과·발표장 네트워크 단절 시에도 100% 서비스 연속성을 보장해야 함
✅ 결과: Bedrock → Groq → Gemini → Claude → OpenAI → 스마트 룰 엔진 + 클라이언트 폴백 완성
ADR-0005
시각화 — 다중 레이어 3D 근육 해부도
💡 왜? 단순 원형 하이라이트는 해부학적 정확도가 떨어져 운동 타겟 부위를 직관적으로 전달하기 어려움
✅ 결과: body_base_neutral.png + 부위별 정밀 overlay_*.png 다중 레이어 실시간 점등 구현

Trial & Error · 공학적 문제 해결
구현 시행착오 및 극복 사례 (4대 핵심 트러블슈팅)

1️⃣ Java + Python 이중 서버 오버엔지니어링

문제: 초기 Spring Boot(8080)와 FastAPI(8000)를 분리했으나 DTO 중복 정의와 서버 간 통신 지연으로 2인 팀 리소스 분산.
해결: 교수님 피드백을 수용해 FastAPI + PostgreSQL 단일 백엔드(ADR-0004)로 전면 통합하여 메모리 점유율 절감 및 개발 속도 3배 향상.

2️⃣ 3D 근육 해부도 원형 블러(drawOval)의 한계

문제: 초기에는 인체 이미지 위에 단순 원형 번짐 효과를 그렸으나 실제 근육 형태와 괴리감이 크고 시각적 완성도가 낮음.
해결: drawOval을 전면 폐기하고 실제 3D 해부도 베이스 + 10개 부위별 정밀 투명 PNG 레이어를 Stack으로 동적 합성해 해결.

3️⃣ LLM 비정형 응답 & 세션 불일치로 인한 루틴 로드 실패

문제: LLM이 간혹 sets/reps에 문자열·null을 반환하거나, 서버 재배포 후 만료 토큰으로 접근 시 추천 루틴 카드가 에러를 표시.
해결: 백엔드 _safe_routine_list 방어 파서 + 데모 세션 자동 복구 + 클라이언트 목표별 스마트 폴백으로 무중단 루틴 표시 달성.

4️⃣ CI/CD 서드파티 SSH 액션 장애 & Flutter 버전 충돌

문제: GitHub Actions 배포 중 appleboy/drone-ssh 504 다운로드 장애 및 CI 최신 Flutter(3.47+)의 deprecated_member_use 실패 발생.
해결: 외부 액션 의존성을 제거하고 Ubuntu 네이티브 OpenSSH 직접 배포로 전환, CI Flutter 버전 고정(3.35.7)으로 해결.
