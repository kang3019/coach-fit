01 · Problem Definition
왜 CoachFit을 만들었는가?
혼자 헬스장에 간 초·중급자의 매일 같은 고민 —
"어제 가슴 운동했는데, 오늘은 무슨 운동을 몇 kg으로 몇 세트 해야 하지?"
5~8만 원 / 회

💸 높은 PT 비용과 루틴 설계 장벽

고가의 1:1 PT 부담 때문에 혼자 시작하지만, 부위별 분할과 점진적 과부하 기준을 몰라 1~2개월 내 중도 포기가 빈번하게 발생합니다.

기록만 100%

📝 단순 수첩에 머무는 기존 운동 앱

기존 인기 앱(Fleek 등)은 세트 기록 UX는 뛰어나지만, 누적된 운동 볼륨·피로도와 체성분을 종합해 "오늘 할 루틴"을 역제안하지 못합니다.

텍스트 나열

🦴 자극 부위의 직관적 시각화 부재

랫풀다운·루마니안 데드리프트 등 생소한 종목명만 나열되어 어느 근육을 쓰는지 감이 오지 않고, 특정 부위 편중·부상 위험이 커집니다.

SOLUTION
3초 다중 세트 기록 UX + 89-Path 정밀 근육 해부도 실시간 점등 + DB 직결(최근 10세션·인바디·목표) AI 맞춤 당일 루틴 & 1:1 코칭을 단일 앱으로 통합

07 · Architecture Decision Records
핵심 기술 의사결정 기록 (ADR-0001 ~ ADR-0005)
ADR-0001
Flutter 단일 코드베이스
왜? 2인 팀이 Android·Web·Windows를 동시 지원하며 AMOLED 다크 테마와 커스텀 차트 일관성을 유지해야 함

ADR-0004 (Supersedes 0002)
FastAPI + PostgreSQL 단일 통합
왜? 초기 Java(8080)+Python(8000) 이중 서버의 DTO 중복과 메모리 부담을 교수님 피드백 수용해 포트 8000 통합
✅ 개발 생산성 3배 향상, 프리티어 EC2(RAM 1GB)에서 OOM 없이 24/7 가동
ADR-0003
5단 멀티 LLM + 이중 폴백
왜? 외부 API 키 유출 위험, 과금 리스크, 발표장 네트워크 장애까지 한 번에 통제해야 함
✅ Bedrock IAM 무키 인증 + 지문 캐시 + 서버/클라이언트 이중 무중단 폴백 완성
ADR-0005
정밀 근육 해부도 고도화
왜? 단순 원형 하이라이트는 해부학적 정확도가 낮아 초보자에게 타겟 자극을 직관 전달 불가
✅ 3D PNG 다중 레이어 거쳐 최종 89-Path SVG 듀얼 뷰(Front/Back) 실시간 점등 완성

10 · Engineering Challenges
개발 중 부딪힌 4대 핵심 시행착오 & 공학적 해결

1️⃣ Java + Python 이중 서버 오버엔지니어링

문제: Spring Boot(8080)+FastAPI(8000) 분리로 DTO 중복 정의, 내부 HTTP 지연, 프리티어 RAM 1GB 압박
해결: FastAPI + PostgreSQL 단일 통합(ADR-0004) → 개발 생산성 3배 향상 & OOM 제로 달성

2️⃣ 근육 해부도 시각적 정밀도 한계 극복

문제: 초기 drawOval 원형 블러는 근육 형태와 괴리가 크고, 단일 PNG는 해상도·인터랙션 확장에 한계
해결: 3D PNG 다중 레이어를 거쳐 89개 정밀 해부학 SVG 패스(Front/Back)로 진화 → 부위 터치 필터링 완성

3️⃣ LLM 비정형 응답 & 재배포 후 세션 만료 오류

문제: LLM이 sets/reps에 문자열·null을 반환하거나 재배포 후 만료 토큰(401)으로 루틴 카드가 깨짐
해결: _safe_routine_list 안전 파서 + 데모 세션 자동 재발급 + 클라이언트 스마트 폴백으로 에러율 0%

4️⃣ CI/CD 서드파티 SSH 504 장애 & Flutter 버전 충돌

문제: appleboy/drone-ssh 다운로드 504 오류 및 CI 최신 Flutter(3.47+)의 deprecated lint 실패
해결: Ubuntu 네이티브 OpenSSH 직접 배포 전환 + CI Flutter SDK 3.35.7 고정으로 배포 100% 안정화
