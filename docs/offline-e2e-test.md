# 오프라인 E2E 검증 절차

네트워크가 끊긴 상태에서 앱이 어떻게 동작하는지 실기기(또는 에뮬레이터)에서 확인하기 위한 절차서입니다.

> ⚠️ **이 문서는 코드 분석으로 작성한 "예상 동작"입니다. 실기기에서 실행해 확인한 결과가 아닙니다.**
> 아래 표의 "예상"과 실제가 다르면 결과 기록란에 남기고 이슈로 등록해 주세요.

## 0. 먼저 알아둘 점 (현재 코드 기준 오프라인 지원 범위)

| 영역 | 오프라인 동작 | 근거 |
|---|---|---|
| 로그인 세션 | ✅ 복원됨 | `AuthService.loadSavedSession`이 SharedPreferences의 토큰/유저 정보를 복원 |
| 프로필 | ✅ 캐시 사용 | `ProfileService`가 캐시로 폴백 |
| 신체 기록 | ✅ 캐시 사용 | `BodyRecordService`가 캐시로 폴백 |
| 목표 | ✅ 캐시 사용 | `GoalService`가 캐시로 폴백 |
| 운동 기록 조회 | ❌ 불가 | `WorkoutService.fetchWorkouts`는 실패 시 예외를 던지며 로컬 캐시 없음 |
| 운동 기록 등록/삭제 | ❌ 불가 | `createWorkout`/`deleteWorkout` 실패 시 예외, **쓰기 큐 없음** (입력값 유실) |
| 주간 통계 | ❌ 불가 | `fetchWeeklyVolume` 실패 시 예외 → 통계 탭 에러 화면 |
| AI 코칭 | ❌ 불가 | `CoachingService` 20초 타임아웃 후 예외 |
| 로그인/회원가입 | ❌ 불가 | 10초 타임아웃 |

**알려진 한계(Known Gap):** 운동 기록은 오프라인 저장/동기화가 구현되어 있지 않습니다. 따라서 "오프라인에서 기록 후 나중에 동기화"는 현재 **지원하지 않는 기능**이며, 이 문서의 목표는 *실패가 앱을 깨뜨리지 않고 명확히 안내되는지* 확인하는 것입니다.

## 1. 준비

- [ ] 테스트 계정 1개 (기록이 몇 건 있는 계정이 좋음)
- [ ] 실기기 또는 에뮬레이터, 최신 `main` 빌드 (`flutter run`)
- [ ] 네트워크 차단 방법 결정
  - 실기기: 비행기 모드 또는 Wi-Fi/모바일 데이터 끄기
  - Android 에뮬레이터: 에뮬레이터 설정 → Cellular/Wi-Fi 끄기, 또는 `adb shell svc wifi disable && adb shell svc data disable` (복구는 `enable`)
  - iOS 시뮬레이터: 호스트 Mac의 네트워크를 끄거나 Network Link Conditioner 100% Loss
- [ ] **반드시 온라인에서 먼저 로그인**하고 홈/기록/통계/프로필을 한 번씩 열어 캐시를 채운 뒤 오프라인으로 전환

## 2. 시나리오

각 항목을 수행하고 결과 기록란에 ✅/❌와 메모를 남깁니다. 타임아웃은 아래 값을 참고해 그 시간 안에 응답이 있는지 확인하세요.

| 서비스 | 타임아웃 |
|---|---|
| 운동 기록(조회/등록/삭제/통계) | 8초 |
| 로그인/회원가입 | 10초 |
| 프로필 | 약 4~5초 |
| AI 코칭 | 20초 |

### A. 콜드 스타트 (온라인 로그인 후 오프라인)

1. 온라인에서 로그인 → 앱 완전 종료
2. 네트워크 차단
3. 앱 재실행

| # | 확인 항목 | 예상 |
|---|---|---|
| A1 | 로그인 화면으로 튕기지 않고 홈에 진입 | 세션 복원 |
| A2 | 홈 닉네임 표시 | 캐시된 프로필 닉네임 |
| A3 | 홈 요약(이번 주 운동 등) | 운동 조회 실패를 삼키고 빈 목록으로 계산 → 0 또는 빈 상태 (※ 실제 기록이 있어도 0으로 보일 수 있음) |
| A4 | 앱이 크래시/무한 로딩 없이 8초 안에 화면 표시 | 예 |

### B. 탭별 동작

| # | 탭/동작 | 예상 |
|---|---|---|
| B1 | 기록 탭 진입 | 불러오기 실패 안내 표시 (캐시 없음). 크래시 없음 |
| B2 | 통계 탭 진입 | "통계를 불러오지 못했습니다" + **다시 시도** 버튼 |
| B3 | 프로필 탭 진입/조회 | 캐시된 프로필 표시 |
| B4 | 신체 기록·목표 조회 | 캐시된 값 표시 |
| B5 | 프로필/신체 기록/목표 수정 저장 | 로컬 저장 동작 여부 확인 (서버 반영은 복구 후 재시도 필요할 수 있음) — 실제 동작을 기록 |

### C. 쓰기 동작 (Known Gap 확인)

| C2 | "오늘 운동 완료 🎉" 버튼 | 실패 안내가 뜨고 완료 모달/햅틱 성공 연출이 **나오지 않아야 함** |

## 3. 판정 기준

- **합격:** 모든 항목에서 크래시·무한 로딩·빈 화면 고착이 없고, 실패가 사용자에게 안내되며, 재연결 후 앱 재시작 없이 복구됨
- **개선 필요(Known Gap):** 오프라인 기록 저장/동기화 부재, 홈 요약이 오프라인에서 0으로 보이는 문제 (현재 설계상 예상된 결과)
