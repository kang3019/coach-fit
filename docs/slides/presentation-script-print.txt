[ Slide 2 — 문제 정의 (Why CoachFit? / 와이 코치핏?) / 35초 (누적 0:50) ]

혼자 헬스장에 간 초보자가 매일 겪는 장벽은
"어제 가슴 운동을 했는데, 오늘 어느 부위를 몇 kg(킬로)로 몇 세트 하지?"라는 막막함입니다.

회당 5~8만 원 PT(피티)는 부담스럽고, 기존 기록 앱은 수첩 기능은 좋지만
누적 데이터를 분석해 오늘 할 루틴을 먼저 제안해주지 못합니다.
또 생소한 종목명만 나열돼 어느 근육에 자극이 가는지 알기 어렵습니다.

저희는 3초 세트 기록, 정밀 근육 해부도, DB(디비) 기록과 직결된 AI(에이아이) 맞춤 루틴을 결합해
이 세 가지 문제를 해결했습니다.

                                       → 전환 키워드: "해결했습니다"

[ Slide 3 — 비전 & 차별점 / 25초 (누적 1:15) ]

CoachFit(코치핏)의 비전은 "기록할수록 똑똑해지는 주머니 속 AI(에이아이) 트레이너"입니다.

표에서 보시듯 기존 앱과 네 가지가 다릅니다.
최근 운동 기록 10건과 인바디를 분석해 오늘 루틴을 제안하고,
원터치로 기록과 자동 휴식 타이머까지 바로 이어집니다.
여기에 89개 해부학 SVG(에스브이지) 근육 맵에 타겟 근육을 실시간으로 점등하고,
외부 AI(에이아이) 장애에도 5단 폴백으로 무중단 동작합니다.

                                       → 전환 키워드: "무중단 동작합니다"

[ Slide 4 — 프로젝트 계획 & WBS(더블유비에스) 100% / 25초 (누적 1:40) ]

2인 팀 일정 리스크를 막기 위해 MoSCoW(모스코우) 기법으로 범위를 통제했습니다.
운동 CRUD(씨알유디), 볼륨 차트, AI(에이아이) 루틴, 스마트 폴백을 Must(머스트) 핵심 기능으로 집중하고,
지연 위험이 큰 카메라 자세 교정과 웨어러블은 Won't(원트)로 과감히 분리했습니다.

20%의 일정 버퍼를 두고 10주차부터 16주차까지 7개 마일스톤,
90개 PR(피알) 병합으로 WBS(더블유비에스) 100%를 달성했습니다.

                                       → 전환 키워드: "100%를 달성했습니다"

[ Slide 5 — 사용자 시나리오 / 35초 (누적 2:15) ]

실제 사용 흐름을 세 명의 페르소나로 살펴보겠습니다.

헬린이 민수 씨가 컨디션을 체크하면, AI(에이아이)가 어제 가슴 운동 기록을 보고
오늘은 등·후면 사슬 루틴을 추천하며 해부도에 타겟 부위를 점등해 줍니다.

직장인 지수 씨는 원터치로 루틴을 담아 세트를 체크하고,
자동 휴식 타이머와 운동 GIF(지아이에프) 가이드로 현장에서 자세를 확인합니다.

중급자 현우 씨는 주간·월간·3개월 볼륨과 인바디 추이를 점검하고,
AI(에이아이) 1:1 전담 코치 채팅으로 부족한 부위를 상담합니다.

                                       → 전환 키워드: "상담합니다"

[ Slide 6 — 핵심 구현 ① AI(에이아이) 루틴 & SVG(에스브이지) 근육 해부도 / 45초 (누적 3:00) ]

핵심 구현 흐름입니다.
홈에서 코칭을 요청하면 FastAPI(패스트 에이피아이)가 DB(디비)에서 최근 운동 기록 10건과 인바디, 목표를 조회해
SHA-256(샤 이오육) 지문 캐시와 대조하고, 기록 변화가 없으면 LLM(엘엘엠) 호출 없이 0.01초 만에 응답을 반환합니다.

프론트엔드는 반환된 종목명에서 타겟 근육을 파싱해
89개 해부학 SVG(에스브이지) 패스에 앞·뒷면 네온 글로우를 실시간으로 점등합니다.

"보시는 것처럼 루틴이 바뀌면 전면과 후면 타겟 근육이 즉시 반응합니다."

[ Slide 7 — 핵심 구현 ② 5단 멀티 LLM(엘엘엠) & 과금 방어 / 30초 (누적 3:30) ]

장애 대응과 비용 통제 설계입니다.
주 엔진은 IAM(아이에이엠) 무키 인증 기반 AWS Bedrock(에이더블유에스 베드락)이며,
환경변수 하나로 Groq(그록)·Gemini(제미나이)·Claude(클로드)·OpenAI(오픈 에이아이) 엔진을 자유롭게 전환합니다.
외부 API(에이피아이)가 모두 실패해도 0.1초 스마트 룰 엔진과 클라이언트 폴백이 이어받아 절대 멈추지 않습니다.

또 지문 캐시와 분당 10회·일 100회 레이트 리미터로 과금 폭탄을 차단하고,
폴백 응답은 캐시에서 제외해 장애 복구 시 즉시 정상 AI(에이아이)로 돌아오도록 설계했습니다.

                                       → 전환 키워드: "설계했습니다"

[ Slide 8 — 아키텍처 의사결정 (ADR / 에이디알) / 25초 (누적 3:55) ]

주요 기술 선택은 5가지 ADR(에이디알)로 문서화했습니다.
그중 핵심 4가지는
첫 번째로, 모바일과 웹을 단일 코드로 배포하기 위해 Flutter(플러터)를 택했고,
두 번째로, Java(자바)+Python(파이썬) 이중 서버의 오버엔지니어링을 해소하기 위해 교수님 피드백에 따라
FastAPI(패스트 에이피아이)와 PostgreSQL(포스트그레 에스큐엘) 단일 백엔드로 통합했습니다.
세 번째로 무키 인증 5단 폴백, 네 번째로 89-Path(팔십구 패스) SVG(에스브이지) 해부도까지 근거와 결과를 검증했습니다.

                                       → 전환 키워드: "검증했습니다"

[ Slide 9 — 클라우드 아키텍처 & 코드 구조 / 25초 (누적 4:20) ]

전체 아키텍처와 모노레포 구조입니다.
클라이언트는 DB(디비)나 LLM(엘엘엠)에 직접 접근하지 않고 AWS(에이더블유에스) 서울 EC2(이씨투) 8000번 포트의
FastAPI(패스트 에이피아이) 단일 서버를 경유하는 BFF(비에프에프) 패턴을 준수합니다.

DB(디비)는 SQLAlchemy(에스큐엘 알케미) ORM(오알엠)으로 RDS(알디에스) PostgreSQL(포스트그레 에스큐엘)과
로컬 SQLite(에스큐엘라이트)를 추상화했고,
Bedrock(베드락)과는 비밀키 저장이 전혀 필요 없는 IAM Role(아이에이엠 롤)로 안전하게 통신합니다.

                                       → 전환 키워드: "통신합니다"

[ Slide 10 — 개발 환경 & CI/CD(씨아이 씨디) 무중단 배포 / 25초 (누적 4:45) ]

개발 환경은 .env(닷 이엔브이) 없이도 클론 후 5분 만에 SQLite(에스큐엘라이트) 시드 데이터로 풀스택 환경이 구동되며,
토글 하나로 EC2(이씨투)와 로컬 오프라인 모드를 전환합니다.

PR(피알)을 올리면 GitHub Actions(깃허브 액션즈)가 pytest(파이테스트) 39건과 flutter analyze(플러터 애널라이즈)를 검증하고,
main(메인) 병합 시 OpenSSH(오픈 에스에스에이치)로 EC2(이씨투) 자동 배포와 systemd(시스템디) 재기동, 헬스체크까지 완료하며
8000번 포트에서 API(에이피아이)와 Flutter(플러터) 웹을 동시 서빙합니다.

                                       → 전환 키워드: "동시 서빙합니다"

[ Slide 11 — 구현 시행착오 4선 / 45초 (누적 5:30) ]

개발 중 해결한 네 가지 핵심 시행착오입니다.

첫째, 이중 서버의 DTO(디티오) 중복과 RAM 1GB(램 1기가) 메모리 압박을 FastAPI(패스트 에이피아이) 단일화로 풀어 생산성을 3배 높였습니다.
둘째, 초기 drawOval(드로우 오벌) 원형 블러의 한계를 극복하기 위해 3D PNG(쓰리디 피엔지) 레이어를 거쳐 89-Path(팔십구 패스) SVG(에스브이지) 듀얼 뷰로 완성했습니다.
셋째, LLM(엘엘엠)의 null(널) 반환과 재배포 후 401(사공일) 토큰 만료 오류는 안전 파서와 데모 세션 자동 복구로 해결해 에러율 0%를 달성했습니다.
넷째, CI(씨아이) SSH(에스에스에이치) 504(오공사) 장애와 Flutter(플러터) 버전 충돌을 네이티브 OpenSSH(오픈 에스에스에이치)와 SDK(에스디케이) 3.35.7 고정으로 안정화했습니다.

                                       → 전환 키워드: "안정화했습니다"

[ Q1 ] "왜 초기 Java(자바) + Python(파이썬) 이중 서버에서 FastAPI(패스트 에이피아이) 단일 백엔드로 바꿨나요?" (Slide 8, 11)

가장 큰 이유는 '2인 팀 규모와 프리티어 인프라에 맞는 아키텍처 최적화'입니다.
초기에는 Spring Boot(스프링 부트, 8080)와 FastAPI(패스트 에이피아이, 8000)를 분리했으나,
동일한 운동 데이터 DTO(디티오)를 양쪽 언어로 중복 정의해야 했고,
서버 간 내부 HTTP(에이치티티피) 통신 지연과 JVM(제이브이엠) 메모리 점유율 문제가 발생했습니다.
지도 교수님의 피드백을 수용해 포트 8000번 FastAPI(패스트 에이피아이) + PostgreSQL(포스트그레 에스큐엘) 단일 백엔드로 통합한 결과,
보일러플레이트가 사라져 개발 속도가 3배 빨라졌고
AWS(에이더블유에스) 프리티어 EC2(이씨투, RAM 1GB / 램 1기가)에서도 OOM(오오엠) 없이 24시간 안정적으로 운영되고 있습니다.

[ Q2 ] "OpenAI(오픈 에이아이)나 Gemini(제미나이) 대신 왜 AWS Bedrock(에이더블유에스 베드락)을 도입했나요? 과금 폭탄 위험은 없나요?" (Slide 7, 9)

두 가지 공학적 이유입니다.
첫째, '무키(Zero-Key, 제로 키) 보안'입니다. 외부 API(에이피아이)는 서버에 비밀키(sk-..., 에스케이)를 저장해야 해 유출 리스크가 크지만,
AWS Bedrock(에이더블유에스 베드락)은 EC2(이씨투)에 부여된 IAM Role(아이에이엠 롤)을 통해 코드에 단 한 글자의 비밀키도 없이 인증됩니다.
둘째, '과금 방어 3중 가드'를 구축했습니다.
SHA-256(샤 이오육) 지문 캐시(CoachingCache, 코칭 캐시)로 같은 날 운동 기록 변화가 없으면 LLM(엘엘엠)을 재호출하지 않고,
AiRateLimiter(에이아이 레이트 리미터)로 사용자당 분당 10회·일 100회·전역 300회 상한을 걸었으며,
평소 테스트 시에는 무료 Groq(그록)이나 내장 스마트 룰 엔진으로 동작하도록 설계했습니다.

[ Q3 ] "코드 흐름을 설명해 보세요 — AI(에이아이) 추천 루틴과 근육 해부도는 어떻게 연결되나요?" (Slide 6)

크게 4단계로 흐릅니다.
1) 클라이언트 요청(CoachingService.requestCoaching / 코칭 서비스 리퀘스트 코칭):
   홈 진입·목표 변경 시 `POST /api/coaching/generate`(포스트 에이피아이 코칭 제너레이트) 호출.
   만료 토큰으로 401(사공일)이 뜨면 데모 세션을 자동 재발급해 재시도합니다.
2) 백엔드 DB(디비) 직결 조회 & 캐시 대조(app/main.py / 앱 메인 닷 파이):
   DB(디비)에서 최근 운동 기록 10건, 최신 인바디, 목표를 조회해
   `coaching_cache.fingerprint()`(코칭 캐시 핑거프린트) 해시를 대조하고 히트 시 0.01초 만에 반환합니다.
3) 멀티 LLM(엘엘엠) 추론 & 안전 파싱(app/services/ai_coach.py / 앱 서비스 에이아이 코치 닷 파이):
   Bedrock(베드락) 등을 호출한 뒤 `_safe_routine_list()`(세이프 루틴 리스트)가
   null(널)/문자열 같은 비정형 응답을 정제하며, 실패 시 0.1초 룰 엔진이 대체합니다.
4) 89-Path(팔십구 패스) SVG(에스브이지) 근육 점등(RecommendedRoutineCard -> MuscleMapWidget / 레코멘디드 루틴 카드에서 머슬 맵 위젯):
   종목명과 focus(포커스) 문자열을 `MuscleGroupExtension.parseFromText()`(머슬 그룹 익스텐션 파스 프롬 텍스트)로 10대 근육 그룹으로 파싱하고,
   `svg_body_data.dart`(에스브이지 바디 데이터 닷 다트)의 89개 해부학 SVG(에스브이지) 패스(전면 40 + 후면 49)에 `#FF4820` 네온 글로우를 실시간 점등합니다.

[ Q4 ] "근육 해부도가 3D PNG(쓰리디 피엔지)에서 SVG(에스브이지)로 바뀐 이유가 뭔가요?" (Slide 6, 11)

시각적 정밀도와 사용자 인터랙션 확장 때문입니다.
1단계 `drawOval`(드로우 오벌) 원형 블러는 실제 근육 모양과 괴리가 커 폐기했고,
2단계 `anatomy_3d_display.dart`(아나토미 쓰리디 디스플레이 닷 다트)의 3D PNG(쓰리디 피엔지) 다중 레이어(베이스 + 10종 투명 PNG/피엔지)로 개선했으나,
다양한 해상도 대응과 개별 근육 터치 필터링에 한계가 있었습니다.
최종 3단계로 89개 정밀 해부학 SVG(에스브이지) 벡터 패스(`svg_body_data.dart` / 에스브이지 바디 데이터 닷 다트)를 적용해
Front/Back(프론트 백) 듀얼 뷰에서 어떤 화면 크기에서도 깨지지 않고, 부위 뱃지 탭 시 즉시 강조·필터링되도록 완성했습니다.

[ Q5 ] "발표장 와이파이가 끊기거나 외부 LLM(엘엘엠) 서버가 죽으면 앱이 멈추지 않나요?" (Slide 7, 10)

절대 멈추지 않도록 '이중 하이브리드 폴백(Dual Fallback, 듀얼 폴백)'을 구현했습니다.
백엔드 단에서 외부 LLM(엘엘엠)이 타임아웃되거나 에러를 내면 0.1초 만에 스마트 룰 엔진이
사용자의 최근 볼륨과 체중 대비 강도를 계산해 루틴을 내려주고,
모바일과 서버 간 네트워크 자체가 끊기거나 레이트 리밋(429, 사이구)에 걸려도
프론트엔드 `CoachingService`(코칭 서비스)가 `CoachingResult.fallback(goal)`(코칭 리절트 폴백 골)을 반환해 홈 화면과 루틴 시작이 100% 동작합니다.
또한 로컬 FastAPI(패스트 에이피아이) + SQLite(에스큐엘라이트) 시드 데이터로 완전 오프라인 시연도 가능합니다.

[ Q6 ] "어디서부터 어디까지 AI(에이아이) 코딩 도구를 썼고, 직접 설계·검증한 부분은 무엇인가요?" (Slide 8, 12)

AI(에이아이) 에이전트는 보일러플레이트 초안 작성, 리팩토링, 문서 구조화에 적극 활용했습니다.
하지만 이중 서버에서 FastAPI(패스트 에이피아이) 단일 통합을 결정한 ADR-0004(에이디알 공사),
근육 해부도를 원형 블러→3D PNG(쓰리디 피엔지)→89-Path(팔십구 패스) SVG(에스브이지)로 진화시킨 UX(유엑스) 설계,
주간·월간·3개월 기간별 볼륨 집계와 이중 폴백 안전망 설계는 저희가 직접 주도했습니다.
특히 모든 코드는 `pytest`(파이테스트) 39건과 `flutter analyze`(플러터 애널라이즈) 경고 0건을 통과할 때만 PR(피알) 병합했습니다.

[ Q7 ] "2인 팀에서 Git(깃) 충돌 없이 어떻게 협업했나요?" (Slide 9, 12)

모노레포 내에서 프론트엔드(`mobile-app/` / 모바일 앱)와 백엔드(`python-ai-backend/` / 파이썬 에이아이 백엔드)를 계층형으로 분담하고,
FastAPI(패스트 에이피아이)가 자동 생성하는 Swagger(스웨거, `/docs` 슬래시 독스) 명세를 단일 API(에이피아이) 계약(Single Source of Truth, 싱글 소스 오브 트루스)으로 삼았습니다.
또한 `AGENTS.md`(에이전츠 닷 엠디) 규칙으로 `main`(메인) 직접 커밋을 금지하고 모든 작업을 `feature/`(피처)·`fix/`(픽스) 브랜치와
GitHub(깃허브) PR(피알), CI(씨아이) 자동 검증(pytest / 파이테스트 + flutter analyze / 플러터 애널라이즈)을 거쳐 병합했습니다.

[ Q8 ] "AWS Bedrock(에이더블유에스 베드락) 크레딧이나 한도를 다 쓰면 어떻게 대처하나요?" (Slide 7, 9)

서비스 무중단 대응, 즉시 엔진 교체, 사전 소진 방지까지 3단계로 대비했습니다.
첫째, 실시간 무중단 폴백입니다. Bedrock(베드락) 크레딧이나 기관 게이트웨이 한도(예: 5만 원 상한)가 소진되어
할당량 초과(429, 사이구)나 결제·권한 에러가 발생하면, `app/services/ai_coach.py`(앱 서비스 에이아이 코치 닷 파이)의
`_fallback_coaching()`(폴백 코칭)이 즉시 감지해 0.1초 만에 내장 스마트 룰 엔진으로 자동 전환합니다.
사용자의 최근 운동 기록·인바디·목표를 그대로 계산해 루틴과 코칭을 제공하므로 서비스가 절대 멈추지 않으며,
폴백 응답은 캐시에서 제외해 한도가 복구되면 즉시 정상 AI(에이아이)로 돌아옵니다.
둘째, 코드 수정 없는 10초 엔진 스위칭입니다. 멀티 LLM(엘엘엠) 추상화 구조 덕분에
서버 환경변수 `AI_PROVIDER`(에이아이 프로바이더) 한 줄만 무료 Groq(그록, Llama 3.3 70B / 라마 3.3 70비)이나
Gemini(제미나이)·OpenAI(오픈 에이아이)로 바꿔 재기동하면 즉시 다른 AI(에이아이)로 교체됩니다.
셋째, 애초에 한도를 조기 소진하지 않도록 방어했습니다. 정형 JSON(제이슨) 루틴 추천은 저렴한 경량 모델(`bedrock-haiku` / 베드락 하이쿠)을,
1:1 자유 채팅에만 고성능 `Sonnet`(소넷)을 배정해 토큰 소모를 줄였고,
SHA-256(샤 이오육) 지문 캐시와 분당 10회·일 100회·전역 300회 레이트 리미터로 과다 호출을 원천 차단했습니다.
