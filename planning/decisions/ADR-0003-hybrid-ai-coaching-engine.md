# ADR-0003: LLM과 로컬 룰베이스를 결합한 하이브리드 AI 코칭 엔진 설계

- **상태**: Accepted
- **날짜**: 2026-09-30
- **결정자**: 2인 프로젝트 팀
- **관련 파일**: `python-ai-backend/app/services/ai_coach.py`

---

## 배경

사용자의 최근 운동 기록을 분석하여 당일 최적의 운동 루틴을 추천해야 합니다. 하지만 상용 LLM(OpenAI, Claude 등) API에만 100% 의존할 경우, **네트워크 지연, 유료 API 토큰 만료, 또는 11월 20일 발표장 인터넷 불안정**으로 인해 시연이 실패할 치명적인 위험이 존재합니다.

---

## 고려한 대안

### 대안 A: 순수 상용 LLM API 단독 의존 (OpenAI `gpt-4o-mini`)
- **장점**: 문맥 이해도가 높고 자연스러운 자연어 피드백 생성
- **단점**: 인터넷 단절 또는 API Key 만료 시 전체 추천 기능 작동 중단 (치명적)

### 대안 B: 정적 하드코딩 룰베이스
- **장점**: 외부 의존성 없음, 응답 속도 극히 빠름(0.01초)
- **단점**: 사용자의 최근 운동 이력(어제 가슴, 그저께 하체 등)에 대한 유연한 맞춤형 코칭 불가

### 대안 C: LLM + 스마트 룰베이스 하이브리드 폴백(Fallback) 엔진
- **장점**:
  - API Key가 있고 인터넷이 연결되면 실제 LLM을 통한 고품질 맞춤형 피드백 제공
  - API Key가 없거나, 네트워크 오류, 타임아웃 발생 시 즉시 로컬 스마트 룰 엔진이 가동되어 0.1초 만에 부위별 피로도를 반영한 최적 루틴 생성
  - 11월 20일 발표 및 교수님 중간 검토 시 100% 무장애 라이브 데모 보장
- **단점**:
  - 두 가지 추천 로직을 모두 구현하고 스키마 일관성을 유지해야 함

---

## 결정

**대안 C (LLM + 스마트 룰베이스 하이브리드 폴백 엔진)**을 최종 채택한다.

---

## 이유

1. **데모 무결성(Demo Integrity)**: 수업 프로젝트 및 최종 발표의 가장 중요한 요소는 "언제 어디서든 에러 없이 동작하는가"입니다.
2. **비용 효율성**: 개발 및 테스트 과정에서 불필요한 유료 토큰 소모 없이 스마트 룰 엔진으로도 자유롭게 기능 테스트 가능.
3. **사용자 경험 보호**: 외부 API 응답이 3초 이상 지연될 경우 사용자의 대기 시간을 줄이고 즉시 결과를 보여줄 수 있음.

---

## 결과 (예상되는 영향)

### 긍정:
- 발표 당일 Wi-Fi가 끊기거나 OpenAI 서버 장애가 발생해도 완벽하게 시연 가능.
- 교수님 Q&A 시 "외부 서비스 장애 대책이 있는가?"라는 질문에 최고의 답변 근거가 됨.

### 부정 / 제약:
- 두 로직 모두 동일한 Pydantic 응답 스키마(`CoachingResponse`)를 반환하도록 DTO 동기화 유지 필요.
