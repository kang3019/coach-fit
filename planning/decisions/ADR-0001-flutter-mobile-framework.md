# ADR-0001: 모바일 클라이언트 프레임워크로 Flutter(Dart) 선정

- **상태**: Accepted
- **날짜**: 2026-09-30
- **결정자**: 2인 프로젝트 팀
- **관련 파일**: `mobile-app/`

---

## 배경

'Fleek(플릭)' 스타일의 피트니스 트래킹 및 AI 코칭 앱을 구현하기 위해, 11월 20일 데모 발표 시연까지 빠르고 완성도 높은 모바일 UI/UX를 구축할 수 있는 프레임워크를 선정해야 했습니다.

---

## 고려한 대안

### 대안 A: Flutter (Google Dart)
- **장점**: 
  - 단일 코드베이스로 Android, iOS 및 Web(Chrome) 동시 실행 가능
  - 세련되고 반응성이 뛰어난 다크 테마 위젯 생태계 풍부 (Fleek 스타일 재현에 최적)
  - 핫 리로드(Hot Reload)로 UI 개발 속도가 극대화됨
  - `fl_chart` 등 피트니스 차트 라이브러리 연동 우수
- **단점**: 
  - Dart 언어에 대한 초기 학습 곡선 존재

### 대안 B: React Native (JavaScript/TypeScript)
- **장점**: 
  - 웹 개발자에게 익숙한 JS/TS 문법
- **단점**: 
  - 네이티브 브릿지 및 패키지 버전 간 의존성 충돌 잦음
  - 차트나 복잡한 애니메이션 구현 시 네이티브 설정 복잡

### 대안 C: Android Native (Kotlin)
- **장점**: 
  - Android OS에 가장 최적화된 성능
- **단점**: 
  - iOS나 브라우저 데모 불가능, 발표장 시연 환경(에뮬레이터/웹) 선택지 제한

---

## 결정

**대안 A (Flutter)**를 모바일 클라이언트 개발 프레임워크로 최종 선정한다.

---

## 이유

1. **시연 환경의 유연성**: 발표 현장에서 실기기 연결, Android 에뮬레이터, Chrome 웹 데모 중 어떤 환경에서도 즉시 실행 가능하여 발표장 리스크를 최소화할 수 있음.
2. **Fleek 스타일 UI 구현 용이성**: 세트 테이블, 다크 모드, 카드형 피드백 등 피트니스 앱에 필수적인 고품질 UI 위젯을 신속히 조립 가능.
3. **생태계 지원**: 차트(`fl_chart`), HTTP 클라이언트, 로컬 스토리지 등 필수 패키지가 성숙함.

---

## 결과 (예상되는 영향)

### 긍정:
- 단일 코드베이스로 빠른 MVP UI 구현 가능 (개발 기간 단축).
- 일관된 렌더링 엔진으로 다양한 모바일 기기 해상도 대응 용이.

### 부정 / 제약:
- 팀원의 Dart 언어 문법 및 Flutter 상태 관리(StatefulWidget/Provider 등) 숙지 필요.
